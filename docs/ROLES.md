# Roles & Permissions

ระบบมี 3 กลุ่มผู้ใช้: **ผู้ใหญ่บ้าน (Admin)**, **ผู้นำชุมชน (Leader)**, **ลูกบ้าน (Villager)**

- Admin/Leader เข้าผ่าน **Web Dashboard** ด้วย username/password (JWT)
- Villager เข้าผ่าน **LINE LIFF** อัตโนมัติ ไม่มี username/password (ใช้ line_user_id)

## Permission Matrix

| Action | Admin | Leader | Villager |
|---|---|---|---|
| Login/Logout (Web Dashboard) | ✅ | ✅ | ❌ (ใช้ LIFF auto-verify แทน) |
| จัดการบัญชีผู้ใช้งาน (user CRUD) | ✅ | ❌ | ❌ |
| เพิ่ม/ร่างข่าว | ✅ | ✅ (รออนุมัติ) | ❌ |
| แก้ไขข่าว | ✅ (ทุกข่าว) | ⚠️ เฉพาะข่าวตนเองที่ยังไม่อนุมัติ | ❌ |
| ลบข่าว | ✅ | ❌ | ❌ |
| อนุมัติ/ปฏิเสธข่าว | ✅ | ❌ | ❌ |
| จัดการหมวดหมู่ข่าว | ✅ | ❌ | ❌ |
| จัดการซอย / คุ้ม (Zone) | ✅ | ❌ | ❌ |
| จัดการปฏิทินกิจกรรม | ✅ | ⚠️ ตามที่ได้รับมอบหมาย | ❌ (ดูอย่างเดียว) |
| จัดการแบบฟอร์มราชการ | ✅ | ⚠️ บางส่วน | ❌ (ดาวน์โหลดอย่างเดียว) |
| เลือกกลุ่มผู้รับ + ส่งข่าวผ่าน LINE | ✅ | ❌ | - |
| ดูประวัติการส่งข่าว/รายงานสถิติ | ✅ | ⚠️ view only บางส่วน | ❌ |
| ตอบกลับแชท 1-on-1 ผ่าน LINE OA | ✅ | ❌ | - |
| ใช้งานแชทบอทถามข้อมูล | - | - | ✅ |
| ดูข่าว/กิจกรรม/ฟอร์มย้อนหลัง | - | - | ✅ |
| รับการแจ้งเตือนข่าวใหม่ | - | - | ✅ |

> ✅ = ทำได้เต็มสิทธิ์ · ⚠️ = ทำได้แบบมีเงื่อนไข · ❌ = ทำไม่ได้ · - = ไม่เกี่ยวข้องกับ role นี้

## Implementation Note

- ใช้ `middlewares/role.middleware.js` เช็คสิทธิ์ทุก route ฝั่ง Admin/Leader โดยดึง `role_id` จาก JWT payload แล้วเทียบกับ `tb_role`
- เงื่อนไข "เฉพาะข่าวตนเองที่ยังไม่อนุมัติ" ของ Leader ต้องเช็คทั้ง `role_id` และ `created_by === req.user.id` และ `news_status !== 'Approved'` ในระดับ controller (ไม่ใช่แค่ middleware)
